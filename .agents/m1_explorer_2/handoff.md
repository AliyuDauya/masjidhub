## 2. Logic Chain

1. **Schema & Migration Parity**:
   - Comparison of `schema.prisma` vs `20250101000000_initial/migration.sql` demonstrates 100% equivalence in tables (9), columns, constraints, foreign keys, and indexes (15).
   - All Prisma SQLite data type mappings (`Int` -> `INTEGER`, `String` -> `TEXT`, `Boolean` -> `BOOLEAN`, `DateTime` -> `DATETIME`) and defaults (`CURRENT_TIMESTAMP`, `'Pending'`, `'Active'`, `'Africa/Lagos'`, `'#087f5b'`, `true`) match exactly.

2. **Foreign Key Cascade and Deletion Semantics**:
   - Multi-tenant tenant deletion cascade: Deleting a `Mosque` cascades to delete its `Membership`, `Program`, `Registration`, `Announcement`, and `Notification` rows, preventing orphaned records.
   - Financial audit protection: Deleting a `User` cascades to `Membership` and `Registration`, but sets `user_id = NULL` on `Donation` records (`ON DELETE SET NULL`) to maintain unbroken financial accounting ledgers.
   - Audit trail protection: Deleting a `Mosque` or `User` sets foreign keys on `AuditEvent` to `NULL` (`ON DELETE SET NULL`), preserving chronological security audit history.
   - Announcement integrity: `Announcement.author_id` is protected with `ON DELETE RESTRICT`, preventing inadvertent author deletion when published notices exist.

3. **Multi-Tenant Boundary Enforcement via Database Constraints**:
   - `Registration` enforces tenant isolation via the composite foreign key `CONSTRAINT "Registration_mosque_id_program_id_fkey" FOREIGN KEY ("mosque_id", "program_id") REFERENCES "Program" ("mosque_id", "program_id") ON DELETE CASCADE ON UPDATE CASCADE`.
   - Backed by the compound unique constraint `Program_mosque_id_program_id_key`, this guarantees at the SQLite engine level that a registration for Tenant A cannot point to a program owned by Tenant B.

4. **Index Design & Query Optimization**:
   - Unique constraints prevent duplicate memberships (`[mosque_id, user_id]`) and duplicate program registrations (`[mosque_id, user_id, program_id]`).
   - Query indexes align directly with backend query patterns in `backend/src/routes/`:
     - `Donation(mosque_id, date)` supports date filtering and CSV export sorting.
     - `Donation(mosque_id, status, reconciliation_status)` supports finance officer reconciliation queues.
     - `Announcement(mosque_id, status, publish_at)` supports public bulletin board queries.
     - `Program(mosque_id, start_date)` supports public timetable ordering.
     - `Notification(mosque_id, user_id, created_at)` supports member notification inbox retrieval.
     - `AuditEvent(mosque_id, created_at)` supports tenant admin audit log retrieval.

5. **Lock File & Migration Execution Integrity**:
   - `migration_lock.toml` correctly locks the migration engine to `sqlite`.
   - `package.json` specifies standard non-interactive deployment command `prisma migrate deploy` for clean environment initialization without interactive prompts.

6. **Seed Script Evaluation & Role Coverage Analysis**:
   - `seed.ts` is strictly idempotent: the sequential `deleteMany` order respects foreign key constraints, allowing repeatable execution without foreign key violation errors.
   - Cross-tenant user verification fixture: User `ali@example.org` has memberships in both `al-noor` and `al-huda`, fulfilling the data requirement for testing multi-mosque global users (Requirement R4).
   - **Role Coverage Gap Identified**: `PROJECT.md` Feature 3 defines: "Idempotent seed script populating demo mosques, 5 roles, programmes, donations". Currently `seed.ts` creates `super_admin`, `tenant_admin`, and `member`, but omits `finance_officer`, `programme_officer`, and `communications_officer`. While permissions can be tested via API invitations, adding dedicated demo accounts for all 5 roles in `seed.ts` improves development experience and testing robustness.

## 3. Caveats

1. **SQLite PRAGMA foreign_keys**: SQLite only enforces foreign key constraints if `PRAGMA foreign_keys = ON;` is enabled on database connections. Prisma Client automatically enforces relations and enables foreign keys by default for SQLite connections, but direct SQLite CLI access must explicitly enable foreign keys if validating outside Prisma.
2. **Seed Role Fixtures vs Runtime Creation**: The omission of `finance_officer`, `programme_officer`, and `communications_officer` in `seed.ts` does not break database integrity or migration history, but represents a minor fixture completeness gap against PROJECT.md Feature 3.
